# Phase 5 placement method

The baseline has six sensing RSUs. `rsu-1` through `rsu-4` are also the four PBFT validators and remain at their original sites. The candidate relocates only `rsu-5` and `rsu-6`; their identifiers, reliability, administrative domains, and detector parameters remain unchanged. `scripts/select_phase5_rsu_placement.py` samples roadside network edges at 50 m spacing and reads vehicle coordinates at five-second intervals from densities 20, 60, and 100, seeds 1001–1006. It uses no attack labels, FN lists, or seed 1007–1010 mobility. It maximizes training positions covered by two RSUs in different 250 m cells, subject to 100 m separation between relocated RSUs and 75 m from fixed RSUs. The frozen selection is in `results/post_seminar_phase5/placement_preregistered.json`: `rsu-5=(150,500)`, `rsu-6=(500,150)` in local network metres. These are road-edge candidate coordinates; physical mounting permissions, power, and line-of-sight are not represented in Scenario 5.

The detector uses a 450 m Euclidean range from true SUMO vehicle position to RSU position. Every in-range RSU runs the label-blind sensor emulator. Each RSU supplies its own signed report for the same original message/root; repeated copies retain that root. The 250 m `geographic_cell` comes from the RSU's position (SUMO net offset 500,500), not the observed vehicle position. The later simulated transport has packet loss, delay, retries, and per-directed-link queues, but no spatial link-budget or coordinate-based path selection. Moving an RSU changes its observations and traffic volume, while the transport graph still uses RSU identities. This is a material limitation for latency and PDR claims.

`scripts/run_phase5_coverage_pilot.py` copies the existing scenario into a separate Phase 5 directory, edits only the RSU JSON and SUMO POI file, and runs SUMO with the same seed. It verifies byte-equal mobility, emitted messages, and ground truth against the original trace before running unchanged B0 and B1. The pilot cells are held-out `(20,1007)` and `(100,1007)`. The original B0 measurements are read from Phase 2. No baseline file is edited.
